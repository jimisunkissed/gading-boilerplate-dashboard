# Style guide

_Last verified: 2026-10-23, against the actual repo contents._

## Part 1 — Code conventions

- **No lint/format config in the repo.** No `.eslintrc*`/`eslint.config.*`, no `.prettierrc*`, no `lint` script in `package.json` (only `dev`/`build`/`start`). Quote style is inconsistent as a result (single quotes in most `lib/` files, double quotes in `app/` and the API templates) — nothing currently enforces one or the other.
- **Exports**: utilities are arrow-function `const`s (`export const doThing = (...) => {}`), not `function` declarations, across every file in `lib/utils/` and `lib/api/`.
- **Naming**: camelCase for functions/variables, PascalCase for types (`ImageMetadata`, `WhereClause`, `ApiSuccess<T>`), kebab-case for filenames (`firebase-mongo-api.ts`, `use-mobile.ts`). **Exception: any field written to a Firestore/Mongo document must be snake_case** (`created_at`, `updated_at`, `first_name`, ...), never camelCase — see `docs/DATABASE.md`. This applies to the document's on-the-wire field names only; the TypeScript variables/params referencing that data stay camelCase as normal.
- **Error handling is layer-dependent — check which layer you're in before assuming a pattern:**
  - `lib/api/firebase-mongo-api.ts` (CRUD/array helpers): catch internally, return `{ error: string }`. Exception: `findOneAndUpdateFirestoreMongo` throws and returns `null` for "not found".
  - `lib/api/firebase-mongo-api.ts` (aggregation helpers — `count`/`sum`/`avg`/`max`/`min`): catch internally, return a bare error **string** (not wrapped in `{ error }`) on failure.
  - `lib/api/r2-api.ts` (storage): throws on failure. Never returns `{ error }`.
  - Route handlers: outer `try/catch` (for thrown exceptions, e.g. from R2 or unexpected failures) **plus** an `isErrorResult()` type guard after every Mongo-helper call (for the `{ error }`-returning helpers) — both are needed, see the templates in `app/api/_template/` for the exact pattern.
- **API routes**: always return the `{ success: true, data }` / `{ success: false, error }` envelope via local `ok()`/`fail()` — see `docs/ARCHITECTURE.md`. Don't invent a different response shape.
- **IDs**: app-generated 20-char strings via `generateFirestoreId()`, never rely on Mongo `ObjectId` formatting/behavior.
- **Path alias**: `@/*` resolves to the repo root — always import via `@/lib/...`, `@/components/...`, never relative-path out of a module's own folder.
- **Runtime-environment split**: `lib/utils/client/*` vs `lib/utils/server/*` is a hard boundary, not just organization — the server files use Node built-ins (`fs`, `os`) and native deps (`sharp`, `fluent-ffmpeg`) that don't run in the browser, and the client files use browser globals (`document`, `canvas`, `window`) that don't exist in a Route Handler.

## Part 2 — Visual/UI conventions

- **Component library**: shadcn, `style: base-nova`, installed via the `shadcn` CLI (`components.json`). Everything under `components/ui/` is a shadcn primitive — there are no custom composed components yet. Icons via `lucide-react` (`iconLibrary: "lucide"` in `components.json`).
- **Stylesheet layout**: `app/globals.css` is only a router — it imports Tailwind, `tw-animate-css`, `shadcn/tailwind.css`, then the files in `app/styles/` in this order: `tokens.css` (raw CSS variables, `:root` light + `.dark`), `theme.css` (`@theme` — exposes tokens/spacing/radius to Tailwind), `base.css`, `utilities/{layout,misc,effects}.css` (custom `@utility`s), `animations/{keyframes,classes}.css`. Don't add rules to `globals.css`; put them in the matching file (or a new file plus an `@import` line). Changing a color or spacing value means editing `tokens.css` / `theme.css`, not components.
- **Colors — semantic tokens only, defined in CSS first.** Components use the semantic roles from `tokens.css`/`theme.css`: `primary`, `secondary`, `background`/`foreground`, `muted`, `border`, `card`, `destructive`, `sidebar-*`, `chart-1`…`5`, and `accent`. Don't write palette classes like `bg-amber-500`, `text-sky-600` or `dark:` pairs in components, and never a raw hex/rgb/oklch literal (`style={{ color: '#...' }}`). Light and dark are handled once, by redefining the variable under `:root` and `.dark` in `tokens.css`, so a component never needs a `dark:` variant for color.
  - **`accent` is the project's tertiary color** — the one hue-bearing role beyond the black/white/grey of `primary`/`secondary`/`muted`. Set its value (and `--accent-foreground`, which must stay readable on it) in `tokens.css` for both `:root` and `.dark`. The shadcn primitives already consume it, so changing it recolors them automatically: the highlighted/focused row in `dropdown-menu`, `context-menu`, `menubar`, `select` and `combobox` (`focus:` / `data-highlighted:` → `bg-accent text-accent-foreground`), and the open-state trigger of the first three (`data-open:` / `data-popup-open:`). The sidebar has its own separate `sidebar-accent` / `sidebar-accent-foreground` pair (hover, active and open menu items) — keep it in step with `accent` by hand. Button, badge, toggle and the other primitives don't use `accent` (they use `primary`/`secondary`/`muted`). **Status: `--accent` is still the template's neutral grey (`oklch(0.97 0.002 106.42)`); no hue has been chosen yet**, so nothing looks accented until it's set. A saturated accent will make those menu rows fully colored on focus, so prefer a light tint with a dark foreground (and the reverse in `.dark`) rather than a strong fill.
  - **Adding a color the roles can't express** (a brand highlight, success/warning status): **add a token first** — define `--success` / `--success-foreground` in both `:root` and `.dark` in `tokens.css`, expose them as `--color-success` / `--color-success-foreground` in `theme.css`'s `@theme inline`, then consume `bg-success` in the component.
  - **Known legacy**: `base.css` has hardcoded `bg-white dark:bg-black` on `html, body` and `bg-orange-100 text-orange-900` for `::selection` — not patterns to copy. The `html, body` rule is also unlayered, so it beats the `bg-background` rule in `@layer base`: in dark mode the page is pure black rather than `--background`. `tokens.css` already has `--selection-bg`/`--selection-text` for the selection colors.
- **Dark mode**: the `.dark` variant and a complete dark palette already exist in `app/styles/base.css` (`@custom-variant dark (&:is(.dark, .dark *))`) and `tokens.css`, but nothing in the codebase currently toggles the `.dark` class — there's no theme switcher/provider. Dark mode is fully wired at the token level and inert at the application level; adding a toggle later should be structural (add the toggle + persist the class), not a token rewrite.
- **Spacing — prefer the named scale over numeric Tailwind values.** `theme.css` defines the rhythm scale as `--spacing-*`, which every spacing utility (`p-*`, `px-*`, `m-*`, `gap-*`, `inset-*`, `space-*`, …) consumes:
  - Fixed (`f` prefix — same at every screen size): `fsm` (1rem), `fmd` (1.5rem), `flg` (2rem), `fxl` (3rem) → `p-fsm`, `gap-fmd`, `mt-flg`, `py-fxl`.
  - Responsive: `rsm`, `rmd`, `rlg` → `p-rsm`, `px-rmd`, `gap-rlg`. They step up at Tailwind's `sm` (40rem) and `md` (48rem) breakpoints automatically (driven by `--r-sm/--r-md/--r-lg` in `theme.css`), so don't add `md:p-8`-style overrides — use the responsive token instead. Use them for page/section/card padding and the gaps between major blocks. Resolved values:

    | token | < 40rem | ≥ 40rem (`sm`) | ≥ 48rem (`md`) |
    |---|---|---|---|
    | `rsm` | 1rem (`fsm`) | 1rem | 1.5rem (`fmd`) |
    | `rmd` | 1rem (`fsm`) | 1.5rem (`fmd`) | 2rem (`flg`) |
    | `rlg` | 1.5rem (`fmd`) | 2rem (`flg`) | 3rem (`fxl`) |
  - **Why not `sm`/`md`/`lg`/`xl`**: Tailwind uses those names for container sizes (`w-md`, `max-w-sm`, `min-w-lg`, `basis-xl`), and it resolves `--spacing-*` before `--container-*`, so a spacing scale named `sm`–`xl` would silently hijack them (shadcn components rely on `max-w-sm`/`max-w-lg`). The `f`/`r` prefixes keep the default width utilities untouched. Don't add spacing tokens named `sm`–`xl` (or any other name Tailwind already uses for a sized scale).
  - Layout: `navtop` (4.5rem, 7rem at `md`) and `navbot` (3rem) are nav heights → `pt-navtop`, `pb-navbot`. Sidebar width is **not** a `theme.css` variable: shadcn's `SidebarProvider` sets `--sidebar-width` inline from the `SIDEBAR_WIDTH` / `SIDEBAR_WIDTH_MOBILE` constants at the top of `components/ui/sidebar.tsx`, and an inline style beats any stylesheet value. To change it, edit those constants (or pass `style={{ '--sidebar-width': '...' }}` to `SidebarProvider`); don't hardcode a `w-64` in the layout.
  - **Allowed exceptions** (numeric values or arbitrary values are fine): padding/margin on buttons, badges, inputs, and text elements, which are usually tuned to the control (`px-3 py-1.5`); and very small gaps (`gap-1`, `gap-2`, `space-y-1`). A dashboard UI is rarely about bespoke spacing, so if a token fits within one step, use the token rather than a custom number. If you find yourself repeating the same custom value, add it to the scale in `theme.css`.
- **Custom utilities** (`app/styles/utilities/`): `page` (full-width column flex container), `bleedx`/`bleedy`/`bleed` (negative margin + equal padding to let a child extend into its parent's padding; bare form uses `rmd`, suffixed form takes any spacing token: `bleedx-fmd`, `bleed-rlg`), `hide-scrollbar`, `scrim` (bottom-fade mask). **Animations** (`app/styles/animations/`): `animate-fadein`, `animate-fadeout`, `animate-unblur`, `animate-slide-fade-{in-from,out-to}-{left,right,top,bottom}`, plus `.parallax` (scroll-driven, only where `animation-timeline` is supported, disabled under `prefers-reduced-motion`). Duration/delay are overridden per element via `--anim-duration` / `--anim-delay` (`style={{ '--anim-duration': '800ms' }}`). Check these before writing one-off CSS.
- **Radius**: corner radius is token-driven off a single `--radius` base (`--radius-sm` through `--radius-xl` are `calc()`s of it in `theme.css`) — don't hardcode `rounded-[Npx]` where a `--radius-*` token fits.
- **Layout primitives**: `TooltipProvider` wraps the whole app in `app/layout.tsx`; `components/ui/sidebar.tsx` is present (full shadcn sidebar system) but not yet mounted anywhere.
- **Typography**: Google Sans is the only font (`--font-sans`, `lib/config/fonts.ts`) — there's no separate mono font; `font-mono` utility classes fall back to Tailwind's default monospace stack. Portal-rendered components (dialog/sheet/drawer/alert-dialog/toast/tooltip) apply the font directly rather than relying on inheritance — see `docs/ARCHITECTURE.md`.
